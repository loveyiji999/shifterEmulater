# SHIFT LAB v1.8.9.1 — QA 驗證報告

## 範圍

本次僅修改桌面 3D 宿主的自動傳動控制策略與手／自排輸入隔離，未修改四輪物理核心、Rapier 車身與地形碰撞程式。

## 執行命令

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
cd desktop3d
npm run qa:transmission
npm run qa:scenarios
```

`archive/legacy/tests/test_v1891_drivetrain.py` 使用 Chromium 直接載入**真實** `physics.html`，以 `d.advancePhysics(1/120)` 執行原四輪物理及齒輪同步器；Three.js 與 Rapier 由於離線依賴缺失未執行。

## 新增重要驗證

| 測試 | 涵蓋範圍 |
|---|---|
| Node 純排檔策略 | 4 車型下升降檔、分離時機、回 1 檔、換檔冷卻、同步器互斥、遲滯 |
| Chromium 真鍵盤事件 | 自排 Shift+數字、R、0、Numpad 不入檔，手排 Shift+數字仍可用 |
| Chromium 模擬換檔要求 | 煞車時自排透過原 `d.requestGear()` 提出降檔、持續同步中不得重複要求 |
| Chromium 真四輪傳動積分 | 標準、城市、渦輪、柴油各 40 秒加速 → 煞車 → 再加速，均降回 1 檔並成功重啟加速 |
| 原核心保護 | physics.html、chassis.mjs、road.mjs、obstacles.mjs、scenarios.mjs 等不變 |

## 保留限制

- 兩項選擇性實車原始量測驗證會因缺少授權原始檔而跳過，與變速箱無關。
- 真正 Three.js／Rapier WASM 的本機 3D 操作及碰撞測試 **尚待玩家執行**；本報告不會將純程式測試誤稱為 3D 實機驗收。
- `Shift+數字` 被取消的是 **自排模式** 下的手動強制排檔；切換手排後，舊同步器的離合器條件、入檔時間及倒檔鎖定仍然有效。
