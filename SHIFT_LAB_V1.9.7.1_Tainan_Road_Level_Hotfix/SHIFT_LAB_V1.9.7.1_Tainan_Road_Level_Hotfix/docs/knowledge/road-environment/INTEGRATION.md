# V3整合定位與驗證規格

本文件定義後續開發的接點與驗收條件；不是已完成材質或場景功能的清單。

2026-10-29更新：既有柏油4條件的逐面綁定、乾濕分界及實際力輸入已實作，見[目前表面驗證](../../P0_SURFACE_BINDING.md)。下方現況表保留研究建立時的唯讀快照，不代表最新版本仍完全使用全域材質。連續地形與新材質仍待P2。

## 當前順序

先通過[所見即所得與環境渲染](rendering/README.md)的地形、材質、光照及效能關卡，再發展賽事功能。畫質降級不得改動近景接觸幾何，後端選擇需同場景量測；本輪仍僅建立知識與規格。

## 資料與物理邊界

後續資料宜分成`surface material`、`surface condition`、`geometry profile`、`biome`與`asset variant`。分類JSON只作知識索引，`runtime_importable=false`；未改動`shiftlab.road.v3`儲存格式。若未來增加儲存欄位，需先定義版本與舊設定重現規則。

道路線形、材質變化、天候與物件分布使用各自從主種子衍生的隨機序列；增加一棵樹不應改變下一個彎道。物件識別使用穩定世界格座標，載入順序或畫面幀率不應改變材質與植栽位置。

依[Rapier碰撞概念](sources/COLLIDER-RAPIER.md)，一般地形可考慮heightfield，重疊道路及洞體保留trimesh。輪胎摩擦仍由原核心接觸力求解；不得額外施加一套地表輪胎力而重複計算。Rapier車身接觸摩擦、輪胎mu、PBR粗糙度是不同欄位，數值不能互相代用。

材質或狀態應由實際命中的碰撞面查得，包含道路層與橫向位置；橋上、橋下及四個輪子均須正確分類。靠全域XY貼圖或最近中心線判斷，可能把下層車輛套成上層材質。

## 後續驗收矩陣

| 類別 | 必須通過的條件 |
| --- | --- |
| 材質 | 10類有可辨識外觀、來源、尺度與狀態；未校準性能維持待定 |
| UV與貼圖 | 彎道、坡道、橋台及chunk邊界不跳紋理；跨段尺度一致 |
| 幾何 | 實際起伏、坑洞與路緣的渲染／碰撞同源；法線貼圖不冒充碰撞 |
| 接觸 | 四輪跨材質邊界及上下層時分類正確；舊車型、傳動及力重置保持 |
| 地形 | 鄰塊無裂縫，挖填方與道路銜接；橋墩、樹根及建物無懸空 |
| 隧道與路口 | 山體不堵洞，植栽不遮路口，原立體交會淨空仍成立 |
| 水系 | 河槽、涵洞、排水出口與水面邊緣一致；未完成水理不標為模擬 |
| 造景 | 同種子重現，避免等距撒點；物件不侵入車道、護欄與結構 |
| 光照 | 標準曝光下材質一致；洞內外、夜間與雨霧可辨識行車面 |
| 效能 | 量測draw calls、三角形、貼圖記憶體、CPU／GPU時間及串流尖峰；先量測再訂門檻 |
| 生命週期 | 重建、切圖與載入失敗後無碰撞體或GPU資源殘留 |
| 相容與隔離 | V1／V2凍結重現、V3單一主線、正式版無驗收UI/API；舊存檔不被靜默改寫 |

本輪驗證限於知識庫、引用與既有檔案保持不變；上述新建模功能尚未開發，也未重新執行遊戲物理測試。
