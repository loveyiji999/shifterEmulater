# 材質資產與渲染規格

本規格以現有Three.js 0.180.0與Rapier 0.18.2為相容基準。線上文件可能較新，新增API或壓縮載入流程需先核對本機版本；本輪不安裝套件、不匯入素材。

## 貼圖與材質

| 資料 | 表達規則 |
| --- | --- |
| Base color與emissive | 顏色貼圖標記`sRGB`；不把光照陰影直接烘入所有基色 |
| Normal、roughness、metalness與AO | 資料貼圖使用`NoColorSpace`；法線方向與通道約定需記錄 |
| glTF金屬粗糙度 | G為roughness、B為metalness；AO若共用圖可放R，但仍需獨立正確綁定 |
| Normal與bump | 改變照明細節，不改變承載面 |
| Displacement | 會改變渲染頂點；行車面需事先產生同源幾何給Rapier，不能只做GPU位移 |
| 葉片與孔洞 | 視需求選alpha mask；透明不會自動改變碰撞 |

色彩空間依[COLOR-THREE](sources/COLOR-THREE.md)，材質功能依[PBR-THREE](sources/PBR-THREE.md)，通道與alpha模式依[GLTF-KHRONOS](sources/GLTF-KHRONOS.md)。工程材質名稱不等於一組固定PBR值，仍需以參考影像及標準光照調整；木、石與混凝土不因濕潤就變為金屬。

道路UV的縱向座標由全域里程決定，橫向座標由實際寬度決定，尺度記錄為公尺。曲線、坡道與chunk邊界不能重新歸零導致拉伸或拼接跳變。岩壁可另評估三平面映射，代價與法線銜接需量測；不把尚未寫入的shader視為現成功能。

## 模型與交換格式

glTF/GLB資產記錄公尺單位、軸向、原點與接地點；匯入時以專案實際座標基底確認轉向，不盲目套用其他引擎的左右軸約定。樹、路燈、石塊、建物及結構拆出穩定的接地基準，避免匯入後仍需逐個人工修正。

資產的外觀模型、簡化碰撞模型與材質變體分別編號。可行駛面沿用相同可見／碰撞幾何；遠景樹冠可降面，但附近樹幹與牆面碰撞不能因鏡頭切換而消失。

## 近中遠景與資源管理

同幾何與材質的物件依chunk／LOD批次實例化，更新實例矩陣及包圍範圍，依[INSTANCE-THREE](sources/INSTANCE-THREE.md)核對生命週期。依[LOD-THREE](sources/LOD-THREE.md)的距離切換及hysteresis概念設計近中遠景；具體距離、面數與陰影預算須用目標硬體測量後決定。透明過繪、陰影、材質數與碰撞成本仍需分開記錄。

共用geometry、material及texture使用明確擁有者或引用計數。移除chunk只釋放其持有資源，避免重複dispose共用資產或每次載入複製整套貼圖。碰撞體、GPU資源和載入快取分別統計，切圖後應回到基線。

RGBA8含完整mipmap的概算為`寬×高×4×4/3`位元組：1024平方約5.33MiB，2048平方約21.33MiB，這是算式而非實測GPU用量。壓縮、通道格式、驅動與對齊會改變結果，不能以下載檔大小代替顯存預算。KTX2、額外後處理或特殊材質擴充需另行驗證依賴與裝置支援。

## 資產來源與授權

每項素材記錄作者、原始URL、授權名稱與版本、取得日期、原始檔hash、修改內容、貼圖通道及模型尺度。文件可公開閱讀不代表圖片或模型可自由重製；先期知識庫僅保存摘要與連結。未確認授權的素材不得進入遊戲資產，來源不明的網圖不作預設貼圖。

後續製作原始資產與研究參考保留在`research/`的分類目錄；測試畫面與量測放在`artifacts/`；只有已確認可用的遊戲資產才進`desktop3d/public/`。本輪未新增任何貼圖、模型或音效。
