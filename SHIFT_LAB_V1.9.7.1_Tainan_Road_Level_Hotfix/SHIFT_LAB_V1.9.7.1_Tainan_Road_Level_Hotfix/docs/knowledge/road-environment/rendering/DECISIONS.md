# 渲染選型與開發順序

使用者已指定環境渲染優先；計時賽、領航、生涯等賽事功能不列為當前里程碑。道路生成仍只有V3開發主線，保留V1／V2凍結相容，既有車輛物理與獨立驗收邊界維持。

## 已確認差距

| 現況 | 環境完成所需改變 |
| --- | --- |
| 純色材質、無道路UV | 公尺尺度材質、正常色彩空間、斜視清晰度及合理混合 |
| 局部路側／山脊／峽谷 | 可連續延伸的山體、挖填方、洞口、橋台與地表接合 |
| 樹、結構或土片可能缺完整地表承接 | 以同一地形與基礎資料完成接地及碰撞檢查 |
| 陰影旗標但未啟用完整陰影流程 | 近景主光陰影、環境照明與固定曝光的畫面對照 |
| pixel ratio上限2，無分級量測決策 | 以實際像素、GPU時間和畫質選擇品質，不一律設最大 |
| 生成及幾何建立在主流程同步執行 | 研究Worker、預載及分批上傳，保留就緒前的有效地表 |
| 現有功能回歸通過 | 新增環境畫質／效能量測；歷史物理PASS不當成新渲染PASS |

## 方法取捨

| 候選 | 本階段判斷 |
| --- | --- |
| 分塊高度場與穩定近景網格 | 優先評估，易與現有Rapier及V3走廊銜接 |
| Geometry clipmaps | 借用過渡與增量原則；是否完整導入取決於遠山規模和實測收益 |
| 全世界體素／即時侵蝕 | 先不作前置依賴；局部洞體與岩壁先用網格解決 |
| 路面UV、局部岩壁三平面 | 優先評估，避免所有表面同時使用昂貴多層投影 |
| KTX2／有界批次與實例化 | 以畫質、轉碼及記憶體共同驗證後採用，不假定固定加速比 |
| WebGPU替換現有WebGL2 | 量測候選，未決定遷移；同場景及相容性通過後才定案 |
| 大量即時光源／全畫面高成本特效 | 逐項量測；先完成主光、接地、山體形狀與材質辨識 |

## 實作關卡

1. 建立可診斷的地表：完整近景地形與道路銜接、碰撞線框、穩定座標及10類材質樣板；確認所見即所得。
2. 完成可看的環境：邊坡、山體、洞口與橋台，加入尺度正確的PBR、主光陰影和環境照明；保留可重現參考畫面。
3. 在同一場景量測並提升：LOD、壓縮、剔除、批次、非同步串流與後端比較，選取指定裝置能穩定維持的最高畫質。

三個關卡皆屬後續實作。本輪交付知識、決策與驗證設計，未開始賽事或修改遊戲渲染器。
