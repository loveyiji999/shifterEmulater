## 開發結論

近期目標是完成一個「車輛與環境所見即所得」的網頁駕駛基礎：車輪、懸吊、車身與碰撞一致；不同路面、邊坡與山體具有可信的形態和材質；在指定裝置上，以量測選取能穩定運行的最高畫質。

採用的順序為：**車輛與場景共用規格 → 基準車可見狀態 → 環境整合 → 畫質與效能定案 → 完整調教 → 外觀創作工具**。車輛規格先於場景細修，完整自訂工具不作為環境渲染的前置工程。

既有物理與變速箱保留為回歸基線。近期沿用現有傳動模型，賽事與生涯後置；WebGL2作為畫質與效能比較基線，WebGPU是否採用由同場景實測決定。

**目前最高優先是定位使用者回報的大量地形載入與車輛碰撞卡頓。**已加入[外部手動效能擷取](PERFORMANCE_MANUAL_CAPTURE.md)，沿用實際玩家設定與正常操作；工具通過不代表卡頓已解決。P2水系、場景銜接與遠景、P3完整量測、P4調教及P5創作仍保留完整交付範圍。

## 使用者已確立的範圍

- 保留種子生成道路與車輛設計，現實城市地圖、圖資及其下載流程不恢復。
- 道路只有V3持續開發；V1／V2維持凍結舊圖相容，不另開平行生成器路線。
- 道路可以交會與上下穿越，必須具備正確層級、淨空、結構、碰撞與通行關係。
- 優先完成環境渲染；玩家能見到的道路、邊坡、山體及障礙，要和實際接觸一致。
- 車輛調教、變速箱設定及外觀創作納入整體方向，需與尺寸、接觸及效能規格共同規劃。
- 物理驗收保留為遊戲外部開發工具；正式遊戲不加入驗收選單、工況或測試API。
- 保留目前啟動位置與雙層版本目錄。patch集中於`archive/patches/`，研究、產物與遊戲資料各自分類。

各階段順序與具體交付是本規劃的綜合建議；目標硬體、詳細數值與創作自由度的待定項目列於後文，不視為已確認規格。

### P0 共用規格與基線

交付車輛定義、調教覆寫、外觀組裝、表面分類與資產能力規則。先以適配層讀取現有`P`／`VEHICLES`，保持四車型及其數值，避免把資料整理變成整套核心重構。

規格需含公尺／質量等單位、座標方向、車長寬高、軸距輪距、輪徑、重心、慣性、懸吊活動範圍、輪組掛點、碰撞外形與材質槽位。保存車輛ID、資產版號、調教版號及驗證規則，明確區分駕駛輔助模式與物理變速箱種類。

同時建立外部開發診斷場景：平地、單輪起伏、斜坡、坡頂、側傾、不同材質分界及上下層。沿用V3或同源生成資料；診斷UI不得進正式遊戲。記錄目標硬體、瀏覽器及原生GPU基線，保留可對照的固定種子、路徑與攝影機。

**驗收：**四預設不變、舊設定可讀、無效規格不能套用；車輛與道路共用尺度一致；量測欄位明確區分實測、估算與未量測。

### P1 基準車與輪組接地

先使用standard作為固定參考車，完成車身可見輪廓、輪組掛點、懸吊壓縮／伸張顯示、轉向及輪胎轉動。從現有物理狀態或其明確衍生資料取得可見位置，不另寫一套彈簧或強制把輪胎吸到地面。

需核對重心位置、模型原點、車身碰撞與可見外形，並保留其他三預設的相容回歸。初期可沿用可追溯的程序模型或合法自製模型；不要求先取得大量精細車模。

提供碰撞線框、輪胎命中點、接觸法線與懸吊行程對照。診斷資料來自實際Rapier及核心狀態，避免顯示一份與接觸無關的理想路面。

**驗收：**平地、單輪壓縮、側坡、離地及落地時，輪組顯示與支撐狀態一致；模型與簡化碰撞的容許誤差有依據；四預設及既有固定步進不變。

### P2 路面邊坡與山體整合

先完成連續基礎地形，再依道路走廊處理挖填方、擋牆、洞口、橋台、橋墩及錨碇。普通山地優先採分塊高度場，懸崖、洞體和多層表面以局部網格補足。鄰塊共享邊界與法線取樣，近景可到達邊坡也需具備碰撞。

道路建立公尺尺度UV與材質槽位，分開混凝土、鋼材、塗裝、路肩及地面。10類路面先完成統一光照的樣板與表面ID；可行駛發布需逐種完成相應的接觸設定及驗證。未校準材質可以在明確標記的開發樣板中預覽，不可靜默沿用乾燥瀝青摩擦假裝已完成。

輪胎依實際命中的面、道路層及區域狀態取得材質。外觀遮罩與接觸邊界同源；在現有核心上整合表面參數，不另外施加重複輪胎力。初期可優先整合瀝青、混凝土、碎石與土路，其餘材質依同一驗收方式加入。

完成主方向光陰影、固定曝光、環境照明與洞內外過渡，再加入有意義的岩石、植被及水系。這一階段的完成判斷是地表、接地、材質及光照形成完整可讀場景，不以擺放物件數量替代。

**驗收：**沒有地形裂縫、懸空支柱、山體堵洞、不可見障礙或跨層材質誤判；基準車能通過代表路面與邊坡；改光照與畫質不改變實際幾何。

### P3 指定硬體上的最高穩定畫質

沿用[渲染量測計畫](knowledge/road-environment/rendering/benchmark-plan.json)的10場景；逐項比較地形LOD、材質層數、KTX2壓縮、剔除、實例化、陰影、後處理、解析度與非同步串流。Worker生成、轉碼及GPU上傳分別限流，切圖時隔離過期資料，渲染與碰撞就緒後再共同啟用。

保留WebGL2現況基線。WebGPU只有在相同場景、功能、材質與可見畫質下通過相容及性能比較，才作遷移決策；兩者使用同一內容與V3資料，不能形成另一條地圖主線。不因新API或更大貼圖直接判定較好。

記錄frame p50／p95／p99、卡頓、CPU分項、可用時的GPU timer、全pass draw calls／triangles、格式對應記憶體估算、資源數及串流延遲。額外記錄模擬時間對牆鐘時間與丟棄步數，避免以物理變慢換取流暢畫面。

60fps是目前計畫參考，並非已達成成績或最高FPS上限。裝置、解析度、記憶體及尾端幀時間門檻需先固定再驗收；無法達標時如實列出畫質、瓶頸與限制，不降低近景接觸正確性。

**驗收：**10場景具可重現的原生GPU數據及移動畫面；暖快取／冷載入分開；長時行駛及切圖無持續資源增長；正式遊戲不帶入性能驗收面板。

### P4 車輛調教與變速箱設定

先完成多方案保存、複製、還原、匯入／匯出與差異顯示，再逐項開放齒比、終傳、煞車、懸吊、輪胎及已支援差速器的設定。每項參數都要有單位、有效範圍、相依條件、套用時機及可觀察效果，不能只增加滑桿。

現有`chooseAutomaticGear()`及介面對六個前進檔有固定範圍。若開放齒數或大幅修改齒比，需一起調整選檔界線、同步器條件、自排策略及PRND回歸；不能只替換參數檔。換檔仍經`requestGear()`及原離合／同步流程，不直接改`state.gear`。

區分可安全即時調整、需停車／重置及需重新建立剛體的參數。更換質量、慣性、輪徑、車高或輪距，要同步更新動力換算、輪組顯示與碰撞；套用失敗保持原設定與有效車輛。

RWD／AWD、變矩器自排、DCT或CVT均另有物理需求，若納入後續範圍須建立對應模型與驗收，不以改名稱或扭力係數代替。本階段先把既有傳動能力做成可靠的自訂資料與工具。

**驗收：**極端與無效輸入可控、方案重載可重現、原四預設結果保留；調教效果同時反映物理與可見車輛；手排、自排、倒檔、N／P及停車限制回歸通過。

### P5 車輛外觀自定義與創作

分三步交付，避免只做塗裝便宣稱完整創作工具已完成。

| 創作層次 | 功能 | 必須同步的資料 |
| --- | --- | --- |
| 塗裝與材質 | 車色、貼紙、材質區域、作品保存 | UV、材質槽、貼圖預算及原始作品來源；初期不隱含改變性能 |
| 模組組裝 | 輪圈、保桿、車身部件與其他支援配件 | 掛點、相容性、外形範圍及明確的質量／碰撞影響規則 |
| 外形創作與匯入 | 受約束的車身尺寸／控制點或網格創作、模型匯入與預覽 | 外形驗證、輪拱與輪組空間、UV／LOD、碰撞重建及必要慣性更新 |

建議第一版以既有四輪車輛拓樸為創作基礎；任意增加車軸、輪數、動力形式或主動空力不默認支援。是否需要完整通用網格建模器，列為獨立產品取捨；先支持可驗證的車身創作與標準資產匯入，不承諾自動理解任意模型。

作品記錄資產版號、部件ID、調教參照、縮放與授權來源。匯入檢查尺寸、座標、外部參照、面數、材質與貼圖預算；保持純資料流程。不能接受看似成功卻輪胎懸空、車殼穿地或GPU資源失控的作品。

**驗收：**自製作品保存與重載一致；車高、輪徑及外形變動的畫面／接觸效果符合規則；不相容作品保留錯誤原因及原作品；通過同一環境與效能門檻。

## 驗證與證據要求

### 必須維持的條件

- Rapier保持車身位置及姿態的單一權威，輪胎力不重複施加；保留每微步force／torque重置。
- 道路及可接觸地形的渲染／碰撞資料一致，頂板、側壁、護欄與其他結構不混入輪胎地面白名單。
- 鏡頭與LOD變動不改變車輪支撐、障礙位置、路面狀態或上下層關係。
- 正式版不包含開發工況、診斷UI、測試API或測試模組；健康檢查保留。

工作目錄為`desktop3d`。以下是後續修改時的檢查指令，不代表本輪重新執行。

## 風險與待定決策

| 風險或待定項目 | 處理方式 | 決定時點 |
| --- | --- | --- |
| 基準車外觀與接觸不一致 | 先完成輪組與碰撞對照，再細修場景 | P1完成前 |
| 不同路面只有外觀、沒有對應接觸 | 表面ID與命中面串接，參數標明估算或校準；不假裝滑水／陷沙已實作 | P2各材質可行駛發布前 |
| 地形／陰影／透明植被導致卡頓 | 持續量測、分塊、批次、限流及品質分級 | P0建立基線，P2／P3逐步定案 |
| 外觀改裝改變質量或碰撞卻未同步 | 建立部件影響與重新計算規則，套用失敗保持舊車 | P0規格、P4／P5驗證 |
| 齒數自訂超出現有六檔假設 | 同時擴充換檔策略及機械／介面驗證 | P4開放前 |
| WebGPU支援或shader不等價 | 保留現況基線，通過同場景比較後再選型 | P3 |
| 自由創作的範圍膨脹 | 明確區分塗裝、模組、受約束車身與通用建模器 | P0定義能力；P5開始前確認產品範圍 |
| 目標硬體與數值未定 | 指定裝置、瀏覽器、解析度、幀時間及記憶體預算；未量測欄位不填假值 | P0；P3驗收前鎖定 |
| 無Git與規格變更 | 修改前保存可恢復快照及hash，按階段小步整合 | 每次實作前 |

本規劃採關卡排程，不承諾未估算的日數或完成百分比。以已通過的P0／P1為基礎，完成下一個P2工作包後再估算後續工作量。未知事項不阻止已明確的資料盤點及基準場景建立，也不授權自行安裝依賴、發布或破壞性操作。

## 近期與後續完成定義

**近期完成P0至P3：**一款可見狀態完整、接地可信的基準車，能在連續地形、不同路面、邊坡、山體及立體結構中行駛；場景與碰撞一致，指定裝置有可重現的畫質與性能成績，其餘三原有車型及舊圖仍相容。

**P2地形工作包：可駕駛的連續地形與道路銜接。**沿用V3中心線、拓樸及結構資料，新增地形不得消耗道路的隨機序列或改變下一個彎道。

1. 建立確定性分塊地表與共享邊界取樣，讓道路走廊外有連續山體與地面；可到達近景由同一頂點／索引建立渲染與碰撞。
2. 依道路工程遮罩銜接挖填方、邊坡、橋台／橋墩及洞口，逐一處理普通地面、上下穿越、隧道與吊橋，保持淨空及輪胎地面分類。
3. 把新增地表接入SurfaceMap，明確區分材質、狀態、參數來源及驗證狀態；新增土路不能靜默當作乾柏油。完成接縫、跨層命中、可駕駛及切圖回收檢查，保存對照畫面和原始資料。

此包完成門檻：共享邊界無裂縫；畫面承載面與碰撞一致；上下層不串接；洞口可通行且支柱接地；重置無殘留；固定種子及四預設回歸成立。此時只完成P2的一部分。

隨後在同一管線加入公尺尺度UV與10類材質樣板，先驗證瀝青、混凝土、碎石與土路可駕駛設定，再完成其餘材質、光照、植被、岩石與水系。P2期間即保存幀時間及資源變化，P3再完成十場景、冷暖載入、三次重複與至少600秒長時行駛的正式比較。
